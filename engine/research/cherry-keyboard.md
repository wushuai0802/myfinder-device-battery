# CHERRY 2.4 GHz 键盘电量（046A:01E0 / 046A:01AC）

## 结论

CHERRY 无线键盘的 2.4G 接收器把电量放在自己的厂商集合里，与 Logitech HID++、Razer
等协议无关。读取只需要一条固定的查询命令，不需要 CHERRY Utility 在运行，也不写任何
配置、固件或配对信息。

## 设备与集合

在 `CHERRY MX 2.0S Wireless PRO`（本机，2026-11-04）上观察到的拓扑：

| 项目 | 值 |
| --- | --- |
| VID:PID | `046A:01E0`（接收器），产品字符串 `MX 2.0S Pro Dongle`，厂商 `CHERRY` |
| USB 形态 | 复合设备，接口 0 = 启动键盘，接口 1 = 键盘/系统控制/消费类/厂商/vendor/鼠标 六个集合 |
| 厂商集合 | `Col04`，usage page `0xFF1C`，usage `0x0092`，接口 1 |
| 报告长度 | 输入与输出均为 64 字节（该集合无 Report ID） |

`046A:01AC`（`CHERRY MX 2.0S`）由上游项目报告为同一协议族，本机未持有该型号。

## 协议

请求（64 字节输出报告，`hidapi` 直接写 64 字节，不加 Report ID 前缀）：

```
04 20 00 1A 06 00 ... (其余补零)
```

回复（64 字节输入报告）：

```
04 20 00 1A 06 00 00 00 LL CC 00 ...
                        ^^ ^^
                        |  +-- byte9: 非 0 表示充电中
                        +----- byte8: 电量百分比 0..100
```

判定条件：`byte1 == 0x20` 且 `0 <= byte8 <= 100`。接收器平时还会主动发
`04 AA 00 AA ...` 心跳报文，`byte1` 不是 `0x20`，必须忽略，不能当作电量
（心跳的 `byte8` 固定为 `0xFF`，直接按百分比解析会得到 255）。

## 证据边界

- 本机 `046A:01E0` 实机读到 `81%`、未充电（2026-11-04，命令 `04 20 00 1A 06`
  一次往返即得回复），验签后的读数与 CHERRY Utility 显示无关，未安装该软件。
- `046A:01AC` 仅有上游 `zcmk123/cherry-battery-state` 的报告，待本项目实测。
- 充电标志只在回复里出现；键盘插线后可能以另一个 PID 枚举为有线键盘，此时接收器
  仍会被查询，但若接收器不再应答则本轮不产生读数。
- 键盘休眠或关机时不会出现 `0x20` 回复，此时不产生卡片，也不编造百分比。

## 安全边界

- 只对 `PIDS` 中列出的两个接收器 PID 发送命令；其他 CHERRY 设备一律不探测。
- 唯一发出的报文是上述只读查询，没有写入、没有固件、没有配对、没有 RGB/键位操作。
- 每个物理接收器一次查询约 1 次输出报告 + 1 次输入报告，耗时不到 5 ms；轮询间隔
  由主程序的后台/面板策略决定（关闭面板时默认 60 秒）。
