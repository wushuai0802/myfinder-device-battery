# CHERRY MX 2.0S WL Pro 电量适配边界

本项目独立实现精确 USB / 2.4G 电量查询。贡献者在 HaloBattery #482 报告了多档百分比和插拔线充电对照；证据等级保持 C，待本项目维护者实机验证。离线自动化测试使用合成帧和 fake 设备，不构成硬件验收。

| 连接 | VID:PID | 精确产品全名 |
| --- | --- | --- |
| 2.4G 接收器 | `046A:01E0` | `MX 2.0S Pro Dongle` |
| USB 有线 | `046A:01DE` | `MX 2.0S WL Pro` |

两个身份都要求 MI_01、`FF1C:0092`，且同一已证明物理 parent 内只有一个候选管理集合。输入和输出分别枚举完整的 button/value caps，只有唯一 report ID `04` 且各自总长度为 64 字节才建立报告证明；任一方向失败、未知、出现其他报告或集合不唯一，都不打开查询句柄、不发送请求。描述符发现只读取元数据，access 为 0；不新增 raw descriptor 回退。

唯一请求是 `04 20 00 1A 06` 后补 59 个零，共 64 字节。合法回复须为 64 字节、前五字节相同、byte7 为 0、byte8 为 1–100、byte9 仅为 0/1（未充电/充电）。0%、越界、未知充电枚举和回显不生成新状态。不增加握手、配置、配对、固件或其他命令，也不提供 DPI 控制。

一次查询只写一次，短写不重试；沿用共享读取器的约 1 秒、最多 32 次输入读取限制，以及现有隔离 manager 的每查询默认 7 秒、整轮 36 秒和两个子进程槽位。同 parent 不重入。输入截止不能保证实际 open/write 可取消。固定诊断区分身份/报告证明拒绝、短写、I/O 失败与无有效回复；公开摘要不超过 48 字符，不增加真实错误或失败退避。

无有效回复只说明没有新读数，不能据此判定设备关机。历史沿用既有保留时效，确认时间和测量时间不刷新，充电恢复未知。两把同型号键盘即使名称相同、百分比接近，也保留独立物理卡片与刷新路由，不做 USB / BLE 名称合并。

## 贡献者证据与待验收事项

#482 贡献者报告：未充电 55%、充电 58%、纯有线 63%，以及随后 59% 与官方一致。拔线/切换后也出现本项目候选读数 60–61%、官方 UI 64% 的短暂差值，即 3–4 个百分点；截图并非同一瞬间，原因不确定，后来的对齐不抹去此前观察。测试中的这些回复前缀独立于请求构造，零尾部为合成填充，不宣称是完整原始抓包。本次验收不沿用贡献者的测试数量或编译结论。

0% 含义、低电量、满电后停止充电、其他状态枚举、长时间睡眠、冷启动/重连、固件差异、官方驱动共存、多把同型号及两传输共存均尚未由本项目维护者验收。数值 100 的软件边界测试不证明满电硬件语义。回复没有事务 ID 或可证明的设备采样时间，无法仅靠这些字段排除格式相同的陈旧帧。

BLE `0687:01DE` 不进入 CHERRY 私有读取器。贡献者报告过系统百分比与 `180F/2A19`；蓝牙继续使用既有 Windows 系统属性路径，充电未知，系统查询时间不是设备采样时间。不新增 GATT 探针。此适配不包含键盘活动监听、打字后即时补读或全局后台轮询时钟变更。
