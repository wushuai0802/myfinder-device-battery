# CHERRY MX 2.0S WL Pro 适配记录

用户型号为 CHERRY MX2.0 WL Pro。以下记录来自同一把键盘，不能推广到 CHERRY 全系列。
基于上游 `fdaa40b`（1.3.10-beta.6）。
本次由用户仅使用 Codex 完成简单适配，并结合用户设备进行对照测试。

| 连接 | 身份与接口 | 电量来源 | 充电状态 |
| --- | --- | --- | --- |
| 2.4G | `046A:01E0`，`MX 2.0S Pro Dongle`，MI_01 / FF1C:0092 | 固定查询回复 `[8]` | 回复 `[9]`：0 未充电、1 充电中 |
| 有线 USB | `046A:01DE`，`MX 2.0S WL Pro`，MI_01 / FF1C:0092 | 相同固定查询 | 相同字节，已取得充电中回复 |
| 蓝牙 BLE | `MX2.0S WL Pro-BT1`，Windows 显示 `0687:01DE` | 现有 Windows 电量属性读取器 | 未提供可验证的充电字段，保持未知 |

USB/2.4G 两个方向均须由描述符证明只有报告 ID `04`，长度均为 64 字节。
管理载荷声明为按钮字段，复用现有 `keyboard_caps` 检查报告 ID。
只发送 `04 20 00 1A 06` 后补零至 64 字节；仅接受相同前缀、长度 64、
状态 `[7]==0`、百分比 `[8]` 为 1–100、充电字节 `[9]` 为 0 或 1 的回复。
不支持零值、其他充电枚举、未知型号或接口，不发送灯效、配对、键位或固件命令。

## 用户设备实测

2026-11-04：2.4G 官方软件显示 58%，未插线，实际回复电量为 58%；
后台活动补读在面板关闭时收到 `keyboard_activity reply_verified`。

2026-11-09 对照（读数随充电持续变化，非同一瞬间截图）：

| 状态 | 用户观察 | 读取结果（前 16 字节） |
| --- | --- | --- |
| 2.4G 未充电 | 官方软件 55%，未充电 | `04 20 00 1A 06 00 00 00 37 00 00 00 00 00 00 00` → 55%、未充电 |
| 2.4G 插线充电 | 官方软件显示充电，56% 后升到 57% | `04 20 00 1A 06 00 00 00 3A 01 00 00 00 00 00 00` → 58%、充电中 |
| 纯有线，接收器已拔出 | 官方软件识别，61%、充电中 | `04 20 00 1A 06 00 00 00 3F 01 00 00 00 00 00 00` → 63%、充电中 |
| 纯蓝牙，线及接收器均拔出 | Windows 63%；官方软件不显示详情 | Windows 属性 64%、连接正常、kind=keyboard |
| 蓝牙档位插充电线 | 用户已插线 | Windows 仍提供 64%；无 USB 管理接口，充电保持未知 |
| 拔线后切回 2.4G | 官方软件 64%，已取消充电标记 | 首个回复 `04 20 00 1A 06 00 00 00 3D 00 ...` → 61%、未充电；随后连续三次 60%、未充电 |

电量对照并非同步采样，两次读取及界面刷新存在时间差，可能产生读取延迟。
拔线后曾出现 3–4 个百分点差异，延迟、两端缓存或切换后的估算调整尚未单独排除；
程序保留设备实际回复，不强制改成官方界面数字。
随后用户确认当前 2.4G 读数为 59%，再次与官方软件一致；前述差值为切换后的阶段性观察。
本地运行版本随后补装充电读取模块，实机返回 68%、charging=true；用户确认卡片已显示充电中。

描述符 release_number：接收器 `0x0107`，有线/蓝牙 `0x0117`；不把它当作官方软件固件版本号。
蓝牙电池服务 `180F` 仅列出 `2A19`（Read, Notify），没有充电状态特征。
复用 `BluetoothProvider`，不对 `0687:01DE` 发送 CHERRY USB 私有查询。
蓝牙属性是系统最近查询，保留 `source_quality=system_property`，无设备测量时间；
属性缺失只保留历史读数，不伪造充电或更新时间。

## 后台刷新

上游 Raw Input 只注册鼠标，键盘输入原本不触发补读。
现在注册鼠标及键盘，只读取消息头的类型与设备句柄，不读取按键码、字符或输入内容。
沿用接收器身份、500 ms 合并、成功前不改变在线状态、一次延迟重试和失败退避。
键盘输入不改变“当前使用的鼠标”托盘选择。
定向补读和 DPI 操作不再推迟完整轮询；关闭面板时由后台定时器控制频率。
蓝牙继续使用现有系统属性查询、事件和定时机制。

## 边界

证据等级保留 C。满电停止充电、低电量、长时间休眠、冷启动、多把同型号键盘及
同时连接两种传输的身份合并尚未实测；不同连接保持独立身份，不能按名称合并。
蓝牙模式充电状态暂不支持，插线本身不能证明正在充电。
