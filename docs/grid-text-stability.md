# 网格文字稳定性

## 症状

相同完整输入在网格面板重复重绘时，少数字形曾出现少量设备像素变化。问题出现在透明文字栅格的重复 native `DrawString` 路径；它不是整张卡片或底图的差异。

## 处理方式

面板标签首次绘制时生成透明的本地文字栅格，后续在输入完全相同且条目仍驻留时，以整数设备坐标复用该栅格。当前底图和裁剪区仍由调用方提供；字体、hint、布局、颜色、DPI、变换和动态文本都纳入输入键，透明底图合成继续生效。缓存最多 256 项、总估算上限 8 MiB，单项超过约 1 MiB 时走原生路径；LRU 淘汰、显式清理和进程退出都会立即释放 `Bitmap`。不预热、不丢首帧、不缓存整张卡片。

## 验证与边界

新增契约覆盖输入失效、原生像素一致性、透明底图合成、clip/translation/DPI/Graphics 状态恢复、fallback、LRU/预算和 `Bitmap` 释放。完整面板验证沿用现有检查；文字聚焦验证使用 `--text-raster`。候选远端 CI：<https://github.com/wushuai0802/myfinder-device-battery/actions/runs/43585268300>。该运行的同进程四个 cold 进程共 128 帧、156 次比较稳定；事后跨进程首次字形比较仍有 12 像素/6 个设备点差异。

因此不保证跨进程首次绘制、淘汰后重新生成或 fallback 的统一，也未证明 Windows 内部成因或长期无泄漏；这些仍是后续证据边界。
